Souls

This was the goth-est name I could think of for those energy-like looking effects. Whilst the shader code for the elements are super straight forward, it was the integration of transparent objects with the render-pipeline of Gaussian Splats that took the engineering grunt.

Gaussian Splats are usually rendered as many small billboard planes meshes, which are then blending together using the GPU's fixed function pipeline. However, this also means their Z values remain written to the Z-buffer, causing incorrect culling if we render naively. To resolve this issue then, a "peeling" post-processing pass was added, which isolated splats, its obscured background, & its surroundings, to create an A/B mask for re/rendering transparent objects back onto these splats without sorting.

The actual scan

Now obviously, I did not clone myself in real life to appear in 5 places at once, to all of our dismays. What happened was, there were 5 scans of me, which were trained into splats, then all "composed" together--a little like lining up images in Photoshop & using the eraser tool to rub off the layer boundaries. Then, to optimise them for the web, this combined scan was re-rendered once again according to the camera path you see on the site, to be retrained once more, creating the most renderer-performant scan possible.

Fixing it in post

The postprocessing chain for this site contains the stylisation, interactivity, & simulation parts--honestly slightly over-engineered. Besides the render peeling described above, the liquid simulation stands as the centrepiece, complementing the DotLottie-controlled ASCII layer, on top of the dithered flavours of the actual scene. This all then ties together, to paint a pretty picture, of me^5.

Self-destruct

This implementation was largely carried over from Deceitville, which is based on an old vulnerability that was supposed to be fixed, a few times. Well, Chromium-based browsers still seem to crash when I spam history.replaceState with an ever-growing string, so I will continue to do it. My theory is that the memory pressure on the IPC process grows faster than the one in the V8 isolate running the JS, crashing it before the JS terminates.
